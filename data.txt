# Autosys → Stonebranch Migration — Copilot Global Instructions

This repo contains Autosys JIL jobs and their Stonebranch UAC conversions.
- JIL source files: /autosys/
- Stonebranch JSON files: /stonebranch/
- Skill instructions: /skills/
- Python scripts: /scripts/
- Mapping/config rules: /config/

## Key Terminology (AutoSys → UAC)
- CMD job → Linux/Unix Task (taskUnix) or Windows Task (taskWindows)
- BOX job → Workflow
- FW job  → Agent File Monitor (taskFileMonitor)
- FT job  → Remote File Monitor (taskFileMonitorRemote)
- start_times → Time Trigger or Cron Trigger
- run_calendar → Calendar (attached to Trigger)
- alarm_if_fail → Failure Action (Email/SNMP Notification)
- Global Variables → Variables

## When user says "validate jobs" → use skills/validate-jobs.md
## When user says "create task" → use skills/create-task.md
## When user says "create trigger" → use skills/create-trigger.md
## When user says "create workflow" → use skills/create-workflow.md
## When user says "fetch task" → use skills/fetch-task.md
## When user says "launch job" → use skills/launch-job.md

Never hardcode credentials. Always read from config/sb_config.yaml + env vars.
Always load config/mapping_rules.yaml for job type context before validating.



skills/validate-jobs.md

# Skill: Validate Autosys → Stonebranch Jobs

## Trigger phrases
"validate jobs", "check conversion", "run validation", "compare jil and json",
"check all jobs", "validate migrated jobs"

## Steps
1. Run: python scripts/validate_jobs.py
   - Parses all .jil files from /autosys/
   - Parses all .json files from /stonebranch/
   - Matches jobs by name (case-insensitive)
   - Validates fields per job type using config/mapping_rules.yaml
   - Checks job type mapping (CMD→taskUnix/taskWindows, BOX→workflow, FW→taskFileMonitor, FT→taskFileMonitorRemote)
   - Checks dependency condition mapping (success, failure, notrunning, done, terminated)
   - Checks trigger/schedule presence if start_times exists in JIL
   - Checks alarm mappings (alarm_if_fail, max_run_alarm, must_complete_times)
   - Assigns each job: PASS / REVIEW / FAIL with specific reasons

2. Run: python scripts/generate_report.py
3. Open reports/validation_report.md and summarize to user:
   - Total counts: PASS / REVIEW / FAIL
   - Top 3 most common failure reasons
   - Jobs that are completely missing from Stonebranch

## Job types handled
CMD → taskUnix or taskWindows
BOX → workflow
FW  → taskFileMonitor (Agent File Monitor)
FT  → taskFileMonitorRemote (Remote File Monitor)


skills/create-task.md

# Skill: Create a Stonebranch Task via REST API

## Trigger phrases
"create a task", "add a new task", "create linux task", "create windows task",
"create file monitor", "push job to UAC"

## Steps
1. Ask user for:
   - Task name
   - Task type: Linux/Unix (taskUnix), Windows (taskWindows), 
     Agent File Monitor (taskFileMonitor), Remote File Monitor (taskFileMonitorRemote),
     Workflow, Timer, SQL, Email, Manual, Approval, Task Monitor, etc.
   - Agent name (Universal Agent name in UAC)
   - Command/script path (for Linux/Unix or Windows tasks)
   - Credentials alias (if applicable)
   - Description (optional)

2. Run: python scripts/sb_api.py create-task \
     --name <name> --type <type> --agent <agent> --command <command>

3. Report back: Task ID, status from UAC response.

## API
POST /resources/task
Refer to config/mapping_rules.yaml for payload structure per type.


skills/create-trigger.md

# Skill: Create a Stonebranch Trigger / Schedule

## Trigger phrases
"create trigger", "add schedule", "set up cron", "create time trigger",
"add a cron trigger", "schedule a task"

## Trigger types available in UAC
- Time: specify dates and times → use for direct start_times migration
- Cron: use Cron syntax → use when AutoSys had cron-style schedules
- Agent File Monitor: trigger on file event → use for FW job triggers
- Temporary: one-time trigger → use for ad-hoc testing
- Composite: multiple event types combined
- Task Monitor / Variable Monitor / Universal Monitor

## Steps
1. Ask user for: trigger name, trigger type, associated task/workflow,
   schedule (cron expression or time), timezone, active/inactive status.
2. Run: python scripts/sb_api.py create-trigger \
     --name <name> --type <type> --task <task> --cron <expr>
3. Report back trigger ID and status.

## API
POST /resources/trigger


skills/create-workflow.md

# Skill: Create a Stonebranch Workflow (BOX equivalent)

## Trigger phrases
"create workflow", "create a BOX", "set up workflow with dependencies",
"add workflow", "migrate BOX job"

## Steps
1. Ask user for:
   - Workflow name
   - List of task names to include as vertices
   - Dependency conditions between tasks (success/failure/success-failure)
   - Entry condition if any
2. Run: python scripts/sb_api.py create-workflow \
     --name <name> --tasks <task1,task2,task3>
3. Report back workflow ID and status.

## Dependency note
AutoSys "success" → UAC "Success"
AutoSys "failure" → UAC "Failure"  
AutoSys "done" / "notrunning" → UAC "Success/Failure" (flag for review)

## API
POST /resources/workflow

skills/launch-job.md
# Skill: Launch / Trigger a Job Manually in UAC

## Trigger phrases
"launch job", "run task", "trigger now", "manually kick off", "test task X"

## Steps
1. Ask user for task name or task ID.
2. ALWAYS confirm before launching:
   "Confirm: launch <task_name> in Stonebranch UAC? (yes/no)"
3. After confirmation, run:
   python scripts/sb_api.py launch-job --name <task_name>
4. Report back: Task Instance ID, initial status (Defined → Waiting → Started → Running).

## Status lifecycle to explain to user
Defined → Waiting → Started → Running → Success / Failed / Cancelled

## API
POST /ops/task/launch
Body: { "name": "<task_name>" }

config/sb_config.yaml

# DO NOT COMMIT WITH REAL CREDENTIALS — use environment variables
stonebranch:
  base_url: "https://your-uac-server:8443/uc"
  username: "${SB_USERNAME}"
  password: "${SB_PASSWORD}"
  verify_ssl: true
  timeout: 30


  config/mapping_rules.yaml

  job_type_mapping:
  CMD:
    stonebranch_type_unix: "taskUnix"
    stonebranch_type_windows: "taskWindows"
    detect_by: "machine_os"           # Detect OS from machine field
    
  BOX:
    stonebranch_type: "workflow"
    
  FW:
    stonebranch_type: "taskFileMonitor"    # Agent File Monitor
    trigger_type: "triggerFileMonitor"
    
  FT:
    stonebranch_type: "taskFileMonitorRemote"   # Remote File Monitor (FTP)

trigger_mapping:
  start_times_simple: "triggerTime"
  start_times_cron: "triggerCron"
  file_event: "triggerFileMonitor"
  one_time: "triggerTemporary"
  
dependency_mapping:
  success: "Success"
  failure: "Failure"
  notrunning: "REVIEW_REQUIRED"    # No direct UAC equivalent
  done: "REVIEW_REQUIRED"          # No direct UAC equivalent
  terminated: "Cancelled"
  
alarm_mapping:
  alarm_if_fail: "failureAction"
  alarm_if_terminated: "cancelledAction"
  max_run_alarm: "lateFinishDuration"
  min_run_alarm: "earlyFinishDuration"
  must_start_times: "lateStart"
  must_complete_times: "lateFinish"
